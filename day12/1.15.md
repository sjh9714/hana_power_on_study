# step26.py 예제

step26.py의 핵심 주제는 "LCEL(LangChain Expression Language)과 RunnableWithMessageHistory를 활용한 대화형 체인 자동화"입니다.

이전 단계(step12.py)에서 수동으로 했던 메시지 결합 및 히스토리 저장을 LangChain의 고수준 추상화 도구를 사용하여 자동화하는 방법을 배웁니다.

---

## 1. 기반 지식 (Core Concepts)

### 1. LCEL (LangChain Expression Language)

* | (파이프) 연산자를 사용하여 여러 구성 요소를 하나의 체인으로 연결하는 선언적 방식입니다.
* prompt | llm 와 같이 흐름이 직관적이며, 내부적으로 스트리밍, 비동기 처리 등이 최적화되어 있습니다.

### 2. RunnableWithMessageHistory

* 가장 중요한 개념입니다. 체인 외부에서 대화 기록을 자동으로 읽고 쓰는 기능을 덧씌우는 래퍼(Wrapper)입니다.
* 개발자가 직접 add_user_message, add_ai_message를 호출할 필요 없이, 실행 시 session_id만 넘겨주면 LangChain이 알아서 히스토리를 관리합니다.

---

## 2. 주요 함수 및 클래스 사용법

### 1. 체인 생성 부분 (create_chain 함수)

```python
chain = (
    prompt
    | llm
)

chain_with_history = RunnableWithMessageHistory(
    chain,
    get_session_history,          # 히스토리를 가져올 함수
     input_messages_key="question", # 사용자 입력이 들어갈 변수명
     history_messages_key="chat_history" # 히스토리가 삽입될 변수명
 )
```

### 2. 체인 실행 및 세션 설정 (chat 함수 내)

```python
for chunk in chain.stream(
    {"question": message}, # 입력 데이터
    config={
        "configurable": {"session_id": session_id} # 세션 식별자 전달
    }
):
    partial_response += chunk.content
```

---

## 3. step12 vs step26 차이점 (Manual vs Automatic)

| 비교 항목     | step12 (Manual)                    | step26 (Automatic / LCEL)              |
|---------------|------------------------------------|----------------------------------------|
| 메시지 결합   | prompt.format_messages() 직접 호출 | LCEL 체인 내부에서 자동 결합           |
| 히스토리 저장 | add_user_message() 등 직접 호출    | RunnableWithMessageHistory가 자동 저장 |
| 코드 가용성   | 로직이 분산되어 있어 복잡함        | 체인 정의가 선언적이라 간결함          |

---

## 4. 코드 로직 분석 (핵심 흐름)

1. 체인 구성: create_chain에서 모델과 프롬프트, 출력 파서를 묶고 히스토리 관리 기능을 추가합니다.
2. 실행 시점: 사용자가 질문을 하면 chain.stream을 호출합니다. 이때 config 매개변수를 통해 현재 대화의 session_id를 전달하는 것이 핵심입니다.
3. 자동 관리:
    * LangChain은 session_id를 보고 store에서 이전 대화 기록을 꺼내 프롬프트에 합칩니다.
    * 모델의 응답이 끝나면, 사용자의 질문과 모델의 답변을 자동으로 store에 저장합니다.

---

## 5. 학습 포인트

* 추상화의 이점: 복잡한 대화 관리 로직을 단 몇 줄의 설정으로 대체할 수 있음을 이해합니다.
* Configurable 파라미터: RunnableWithMessageHistory를 쓸 때 config를 통해 외부 변수(session_id)를 전달하는 패턴을 익힙니다.
* LCEL의 확장성: 나중에 검색기(Retriever) 등을 추가할 때도 | 연산자로 쉽게 확장할 수 있다는 점을 인지합니다.

정리: step26은 LangChain의 표준적인 개발 방식(Best Practice)에 가장 근접한 단계입니다. 수동으로 관리하던
번거로운 작업들을 프레임워크에 맡기고, 개발자는 비즈니스 로직(프롬프트, 모델 선택 등)에만 집중할 수 있게
됩니다.
