# LCEL 이란?

LangChain에서 **LCEL(LangChain Expression Language)** 은 LangChain 컴포넌트들을 파이프(`|`) 형태로 연결하여 체인을 만드는 방식입니다.

쉽게 말하면:

> "Prompt → LLM → OutputParser → Retriever → Custom Function"

같은 흐름을 매우 직관적으로 연결하는 문법입니다. ([LangChain][1])

---

## 1. LCEL이 등장한 이유

예전 LangChain에서는 주로 다음과 같은 방식으로 체인을 만들었습니다.

```python
from langchain.chains import LLMChain

chain = LLMChain(
    llm=llm,
    prompt=prompt
)

result = chain.run("AI")
```

하지만 프로젝트가 커질수록

* Prompt 변경
* 모델 변경
* Parser 추가
* Retriever 연결
* Streaming 추가

등이 복잡해졌습니다.

그래서 LangChain은 **"Runnable" 기반의 LCEL** 을 도입했습니다. ([LangChain][1])

---

## 2. LCEL 핵심 개념

모든 컴포넌트는 Runnable 입니다.

예를 들면

```python
Prompt
↓
LLM
↓
OutputParser
```

를

```python
prompt | llm | parser
```

로 표현합니다.

---

## 3. LCEL의 가장 큰 특징

## 3-1. 파이프라인 방식

Linux Shell과 비슷합니다.

```bash
cat file.txt | grep hello
```

처럼

```python
prompt | llm | parser
```

내부적으로 거의 다음과 비슷합니다.

```python
def chain(input_data):

    prompt_result = prompt.invoke(input_data)

    llm_result = llm.invoke(prompt_result)

    parser_result = parser.invoke(llm_result)

    return parser_result

```

즉 파이프는 단순히

```bash
출력 → 다음 입력
```

을 자동 연결하는 문법입니다.

---

## 3-2. 가독성이 매우 좋음

기존:

```python
chain = LLMChain(
    llm=llm,
    prompt=prompt
)
```

LCEL:

```python
chain = prompt | llm
```

---

## 3-3. 모듈 교체가 쉬움

GPT → Gemini 변경

```python
chain = prompt | openai_model
```

↓

```python
chain = prompt | gemini_model
```

---

## 3-4. Streaming 지원

```python
chain.stream()
```

---

## 3-5. Async 지원

```python
await chain.ainvoke()
```

---

## 3-6. Batch 처리 지원

```python
chain.batch()
```

---

## 3-7. LangSmith 추적 지원

LCEL 체인은 자동으로 추적(Tracing)이 가능합니다. ([LangChain][1])

## 4. LCEL 구조

기본 구조는 다음과 같습니다.

```text
Input
  ↓
Prompt
  ↓
LLM
  ↓
OutputParser
  ↓
Output
```

---

예를 들면:

```python
사용자 질문
     ↓
PromptTemplate
     ↓
GPT
     ↓
StrOutputParser
     ↓
최종 문자열
```

## 5. StrOutputParser 란

`StrOutputParser`는 LangChain에서 **LLM의 출력 결과를 문자열(String)로 변환하는 역할**을 합니다.

초보자가 LangChain을 배울 때 가장 헷갈리는 부분 중 하나가 바로 이것입니다.

---

### 7. OutputParser 종류

LangChain에는 여러 Parser가 있습니다.

| Parser                         | 역할                |
| ------------------------------ | ------------------- |
| StrOutputParser                | 문자열 반환         |
| JsonOutputParser               | JSON 반환           |
| PydanticOutputParser           | Pydantic 객체 반환  |
| CommaSeparatedListOutputParser | 리스트 반환         |
| XMLOutputParser                | XML 반환            |

---

### 8. 기억해야 할 핵심

`StrOutputParser`는 **LLM이 반환하는 `AIMessage` 객체를 사람이 사용하기 쉬운 `str` 문자열로 변환하는 가장 기본적인 Output Parser**입니다.

```text
Prompt
   │
   ▼
LLM
   │
   ▼
AIMessage
   │
   ▼
StrOutputParser
   │
   ▼
String
```

그래서 LCEL에서는 거의 습관적으로 다음 형태를 사용합니다.

```python
prompt | llm | StrOutputParser()
```

이 패턴은 ChatBot, RAG, Router Chain, Agent 등 대부분의 LangChain 예제에서 가장 많이 등장하는 기본 구조입니다.

## 6. Runnable 이란?

LCEL의 핵심입니다.

Runnable은

```python
입력
 ↓
처리
 ↓
출력
```

을 가지는 객체입니다.

예:

```python
PromptTemplate
ChatOpenAI
Retriever
OutputParser
```

모두 Runnable 입니다. ([langchain-opentutorial.gitbook.io][3])

---

## 7. RunnableLambda

직접 함수를 체인에 넣을 수도 있습니다.

```python
from langchain_core.runnables import RunnableLambda

def upper(text):
    return text.upper()

upper_chain = RunnableLambda(upper)
```

---

사용

```python
chain = (
    prompt
    | llm
    | parser
    | upper_chain
)

result = chain.invoke(
    {"topic":"ai"}
)

print(result)
```

## 8. RunnableLambda 예제

질문 → GPT → 대문자 변환하는 예제 입니다

>파일명: step19.py

```python
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_core.runnables import RunnableLambda

#소문자를 대문자로 변환하는 람다 함수
def upper(text):
    return text.upper()

llm = ChatOpenAI(
    model="gpt-4.1-mini"
)

prompt = PromptTemplate.from_template(
"""
질문:
{question}
"""
)

chain = (
    prompt
    | llm
    | StrOutputParser()
    # 응답을 대문자로 변환하는 람다 함수 추가
    | RunnableLambda(upper)
)

for chunk in chain.stream({"question":"ai"}):
    # 스트리밍된 응답을 실시간으로 줄바꿈 하여 출력 
    print(chunk)
```

실행 결과 확인시 영문대자로 출력된 것을 확인

```bash
DOCKER란 무엇인가에 대한 설명입니다.

DOCKER는 컨테이너 기반의 가상화 플랫폼으로, 애플리케이션과 그 실행에 필요한 모든 환경(라이브러리, 설정 파일 등)을 하나의 패키지인 컨테이너(CONTAINER)로 묶어 어디서나 동일하게 실행할 수 있도록 해주는 도구입니다.

주요 특징은 다음과 같습니다:

1. **가벼운 가상화**: 기존의 가상머신(VM)과 달리 운영체제 전체를 가상화하지 않고, 호스트 OS의 커널을 공유하여 컨테이너를 실행하기 때문에 훨씬 가볍고 빠릅니다.
2. **이식성(PORTABILITY)**: 컨테이너 안에 애플리케이션과 환경이 모두 포함되어 있어, 개발 환경, 테스트 환경, 운영 환경 등 다양한 곳에서 동일하게 실행할 수 있습니다.
3. **빠른 배포와 확장성**: 컨테이너 이미지로부터 빠르게 컨테이너를 생성하여 배포할 수 있으며, 여러 개의 컨테이너를 손쉽게 확장할 수 있습니다.
4. **격리성**: 각 컨테이너는 독립적으로 실행되어, 서로 간섭 없이 애플리케이션을 구동할 수 있습니다.

요약하면, DOCKER는 애플리케이션 실행 환경을 표준화하고 경량화하여 개발, 배포, 운영 과정에서 효율성과 일관성을 제공하는 도구입니다.
```

다음에는

```python
 | RunnableLambda(upper)
```

이부부을 주석처리하고 실행하면 위와 영문이 대소문자로 출력되는 것을 확인할 수 있습니다

## 10. RunnablePassthrough

RunnablePassthrough란?

입력값을 변경하지 않고 그대로 다음 단계로 전달하는 Runnable 입니다
예을 들어 질문을 두 군데에서 사용하고 싶을 때, 1. 검색에도 사용, 2. 프롬프트에도 사용하고 싶습니다.
일반적인 경우 입력값을 각각 두 군데 전달시 변수를 사용하여 전달합니다.
그런데 이런 경우 실수가 발생할 수 있습니다.  RunnablePassthrough과 LCEL 구문을 사용하면 다음 단계로 실수 없이 값을 전달하여 정확하게 처리할 수 있습니다

---

### 예제 1 : "아무것도 안 하는 함수"

일반 Python 코드

>파일명 : step20.py

```python
def passthrough(x):
    return x
```

실행

```python
print(
    passthrough("안녕하세요")
)
```

결과

```text
안녕하세요
```

입력한 값을 그대로 반환합니다.

`RunnablePassthrough`도 동일합니다.

### 예제 2 : RunnableLambda 와 비교

### RunnablePassthrough

>파일명 : step22.py

```python

chain = RunnablePassthrough()

    chain.invoke(10)

```

결과

```text

```

---

### RunnableLambda

```python
from langchain_core.runnables import RunnableLambda

chain = RunnableLambda(
    lambda x: x * 10
)

print(
    chain.invoke(10)
)
```

결과

```text
100
```

---

비교

```text
RunnablePassthrough

10
 │
 ▼
10


RunnableLambda

10
 │
 ▼
100
```

위와 같이 RunnablePassthrough 클래스는 전달된 값을 수정하지 않고 그대로 다음 단계로 전달을 합니다
RunnableLambda 클래스는 전달된 값을 원하는 로직에 맞게 계산을 하고 다음 단계로 전달을 합니다

즉 인자값을 변형하는지 하지 않는지의 차이입니다

    "question": RunnablePassthrough()

### 한 문장으로 설명

`RunnablePassthrough()`는

> **입력 데이터를 수정하지 않고 그대로 다음 단계로 전달하는 Runnable** 입니다.

그래서 RAG에서는 거의 항상 다음 패턴으로 사용됩니다.

```python
{
    "context": retriever,
    "question": RunnablePassthrough()
}
```

의 의미는

```text
사용자 질문

"RAG란?"
     │
     ├── Retriever에게 전달
     │
     └── Prompt의 question 변수에도 그대로 전달
```

즉, **"원본 입력을 유지하면서 다른 작업과 함께 사용하기 위한 분기(Branch) 역할"** 이라고 이해하면 가장 쉽습니다.

## 11. 기존 Chain 방식 vs LCEL

| 항목           | 기존 Chain     | LCEL      |
| -------------- | -------------- | --------- |
| 코드 길이      | 길다           | 짧음      |
| 가독성         | 보통           | 높음      |
| Streaming      | 제한적         | 강력      |
| Async          | 복잡           | 쉬움      |
| Batch          | 복잡           | 쉬움      |
| Runnable 조합  | 어려움         | 쉬움      |
| LangSmith 추적 | 추가 작업 필요 | 자동 지원 |

([LangChain][1])

## 12. 실제로 가장 많이 사용하는 LCEL 패턴

```python
chain = (
    prompt
    | llm
    | StrOutputParser()
)
```

그리고 RAG에서는

```python
retriever
    | prompt
    | llm
    | parser
```

또는

```python
{
    "context": retriever,
    "question": RunnablePassthrough()
}
| prompt
| llm
| parser
```

형태를 가장 많이 사용합니다.

## 13. 한 줄 요약

LCEL은 LangChain의 최신 체인 작성 방식으로, `Runnable`들을 `|` 연산자로 연결하여 **가독성, Streaming, Async, Batch, 병렬 처리, LangSmith 추적**을 쉽게 사용할 수 있게 해주는 LangChain의 핵심 문법입니다. 현재 LangChain 실무에서는 기존 `LLMChain`보다 LCEL 방식이 사실상 표준으로 사용되고 있습니다. ([LangChain][5])
