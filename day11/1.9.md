# step08.py 예제

step08.py의 핵심 주제는 "모델의 교체 및 확장성(Model Interchangeability)"입니다. LangChain의 가장 큰 장점 중 하나인 '코드의 큰 수정 없이 모델 공급자(OpenAI → Google Gemini)를 바꾸는 방법'을 배웁니다.

---

## 1. 기반 지식 (Core Concepts)

### 1. 모델 독립성 (Model Agnostic)

* LangChain은 다양한 LLM 공급자(OpenAI, Google, Anthropic 등)를 동일한 인터페이스로 다룰 수 있게 설계되었습니다.
* llm.invoke()나 llm.stream() 같은 표준 함수를 사용하면, 내부 모델이 무엇이든 상관없이 동일한 방식으로 코드를 작성할 수 있습니다.

### 2. Google Gemini (Generative AI)

* 구글에서 개발한 최신 멀티모달 모델입니다.
* 이 예제에서는 gemini-2.5-flash 모델을 사용하며, 이는 속도가 빠르고 효율적인 모델입니다.

---

## 2. Gemini API 키를 만들고 싶은 경우

LLM(Gemini)을 활용한 개발, Ollama/Open WebUI 연동, 개인 프로젝트 등에 사용할 키가 필요하다면 **Google AI Studio**에서 가장 빠르고 간편하게 발급받을 수 있습니다.

1. **[Google AI Studio](https://aistudio.google.com/)** 사이트에 접속하여 구글 계정으로 로그인합니다.
2. 약관 동의 화면이 나오면 동의를 진행합니다.
3. 왼쪽 상단 메뉴에서 **"Get API key"** 버튼을 클릭합니다.
4. **"Create API key"** 버튼을 클릭합니다.
5. 기존에 만들어둔 구글 클라우드 프로젝트가 있다면 선택하고, 없다면 "Create API key in new project"를 선택하여 새 프로젝트와 함께 키를 생성합니다.
6. 생성된 API 키를 복사(Copy)하여 안전한 곳에 저장합니다.

## 3. 주요 함수 및 클래스 사용법

### 1. ChatGoogleGenerativeAI 클래스

구글의 Gemini 모델을 사용하기 위한 LangChain 클래스입니다.

* 패키지 설치:

```bash
pip install langchain-google-genai
```

* API 키: OpenAI 대신 구글 AI 스튜디오에서 발급받은 GOOGLE_API_KEY가 필요합니다.

```python
from langchain_google_genai import ChatGoogleGenerativeAI

llm = ChatGoogleGenerativeAI(
    model="gemini-2.5-flash",        # 구글의 최신 모델명
    google_api_key=os.getenv("GOOGLE_API_KEY"),
    temperature=0.7,
    streaming=True
)
```

### 2. 일관된 인터페이스 사용

step07과 비교했을 때, 모델 객체를 생성하는 부분만 바뀌었을 뿐 그 아래의 prompt.format_messages(),
llm.stream(messages) 등 모든 로직이 동일함을 확인할 수 있습니다. 이것이 LangChain을 쓰는 이유입니다.

## 3. 코드 로직 분석 (변화점 위주)

1. 라이브러리 변경: langchain_openai 대신 langchain_google_genai를 임포트합니다.
2. 환경 변수 변경: OPENAI_API_KEY 대신 GOOGLE_API_KEY를 불러와 사용합니다.
3. 나머지 로직 유지: PromptTemplate, MessagesPlaceholder, Gradio History 처리 로직은 완전히 동일합니다.

## 4. 학습 포인트

* 추상화의 힘: 모델 하나를 바꿔도 전체 코드를 갈아엎을 필요가 없다는 점을 직접 확인하세요.
* Gemini의 특징: OpenAI 모델과 비교했을 때 답변의 스타일이나 속도, 말투 등이 어떻게 다른지 느껴보세요.
* 확장성 설계: 나중에 자체 모델(Llama 등)을 쓰게 되더라도 LangChain의 구조를 유지하면 쉽게 교체가 가능하다는 것을 이해하는 것이 중요합니다.

정리: step07은 OpenAI 기반, step08은 Google Gemini 기반입니다. 두 파일의 코드를 나란히 두고 비교해보면 LLM 객체 생성 부분 외에는 거의 똑같다는 것을 발견하실 수 있습니다. 이것이 바로 LangChain이 추구하는 유연성입니다.
