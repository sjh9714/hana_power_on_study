# step11.py 예제

step11.py는 이 튜토리얼의 최종 완성형으로, 핵심 주제는 "Gradio Blocks를 활용한 커스텀 UI 구축과 정교한 상태 관리"입니다. 단순한 채팅창을 넘어 실제 웹 애플리케이션에 가까운 구조를 만드는 방법을 배웁니다.

---

## 1. 기반 지식 (Core Concepts)

### 1. gr.ChatInterface vs gr.Blocks

* ChatInterface: 사용법은 간단하지만 레이아웃 변경이 어렵습니다.
* Blocks: 사용자가 원하는 대로 화면을 배치할 수 있는 저수준(Low-level) API입니다. 버튼 위치, 텍스트 상자 크기, 마크다운 설명 등을 자유롭게 구성할 수 있습니다.

### 2. 상태 관리의 수동 제어

* ChatInterface는 대화 기록(history)을 자동으로 관리해주었지만, Blocks에서는 개발자가 직접 history 리스트에 사용자 메시지와 AI 메시지를 추가하고 관리해야 합니다.

### 3. 이벤트 바인딩 (Event Binding)

* "전송" 버튼을 눌렀을 때(click)와 텍스트 상자에서 엔터를 쳤을 때(submit) 각각 어떤 함수를 실행하고, 어떤 UI 요소를 갱신할지 명시적으로 연결합니다.

---

## 2. 주요 함수 및 컴포넌트 사용법

### 1. UI 레이아웃 컴포넌트

* gr.Blocks(): 전체 애플리케이션의 컨테이너입니다.
* gr.Row(): 내부 요소들을 가로로 배치합니다.
* gr.Column(): (본문엔 없으나 Row와 짝꿍) 세로로 배치합니다.
* scale 인자: gr.Row 안에서 요소 간의 상대적인 너비 비율을 정합니다 (예: 텍스트 상자 8, 버튼 1).

### 2. chat 함수의 변화 (출력 구조)

이제 함수는 단순히 스트리밍 문자열만 내보내는 게 아니라, [갱신된 대화 기록, 초기화할 입력창 내용] 두 가지를 동시에 반환합니다.

```python
1 # history[-1]은 방금 추가한 빈 assistant 메시지입니다.
2 history[-1]["content"] = partial_response
3 yield history, "" # 첫 번째는 chatbot UI에, 두 번째는 msg(텍스트상자) UI에 매핑됨
```

### 3. 이벤트 연결 로직

```python
send_btn.click(
    fn=chat,
    inputs=[msg, chatbot, model_dropdown], # 입력 받을 컴포넌트들
    outputs=[chatbot, msg]                 # 결과값을 반영할 컴포넌트들
)
```

---

## 3. 코드 로직 분석 (고급 기법)

1. 방어적 코딩 (Error Handling): try...except 문을 사용하여 모델 호출 중 오류가 발생해도 프로그램이 멈추지 않고 화면에 에러 메시지를 표시하도록 했습니다.
2. 데이터 구조 확인: hasattr(chunk, "content")를 사용하여 스트리밍되는 데이터 조각이 실제 텍스트 내용을 가지고 있는지 안전하게 체크합니다.
3. UI 흐름:
    * 질문 전송 → chat 함수 호출.
    * chat 내부에서 즉시 history에 사용자 질문 추가 → 화면 갱신.
    * AI 답변이 오는 동안 history의 마지막 요소를 계속 업데이트하며 yield.
    * 동시에 질문 입력창은 ""(빈 문자열)로 비워줌.

---

## 4. 학습 포인트

* 커스터마이징 능력: Blocks를 통해 내가 원하는 위치에 로고를 넣거나 설정 창을 별도로 만드는 등 UI를 확장하는 법을 익힙니다.
* 데이터 바인딩의 이해: UI 컴포넌트의 값이 함수의 인자로 들어가고, 함수의 반환값이 다시 UI에 어떻게 그려지는지(Inputs → Fn → Outputs) 그 메커니즘을 완벽히 이해하는 것이 중요합니다.
* 예외 처리: 실제 서비스 환경에서 발생할 수 있는 네트워크 오류나 API 키 문제 등을 사용자에게 어떻게 보여줄지 고민하는 단계입니다.
