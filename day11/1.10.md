# step09.py 예제

step09.py의 핵심 주제는 "멀티 모델 지원 및 팩토리 패턴(Factory Pattern)의 기초"입니다. 이전 단계들(step07, step08)에서 개별적으로 다뤘던 OpenAI와 Google Gemini를 하나의 코드에서 선택적으로 사용할 수 있도록 구조화하는 방법을 배웁니다.

---

## 1. 기반 지식 (Core Concepts)

### 1. 팩토리 패턴 (Factory Pattern)의 기초

* 객체 생성을 직접 하지 않고, 생성 전담 함수(get_llm)를 통해 필요한 객체를 받아오는 방식입니다.
* "어떤 모델을 쓸 것인가?"라는 결정 로직을 함수 내부에 격리시켜, 메인 코드의 복잡성을 줄입니다.

### 2. 모델 추상화와 다형성 (Polymorphism)

* ChatOpenAI와 ChatGoogleGenerativeAI는 서로 다른 클래스이지만, LangChain에 의해 stream(), invoke() 등  사용법(인터페이스)이 동일하게 설계되었습니다.
* 덕분에 모델이 바뀌어도 그 뒤의 프롬프트 적용 및 대화 로직은 수정할 필요가 없습니다.

---

## 2. 주요 함수 및 클래스 사용법

### 1. get_llm(provider) 함수 (사용자 정의)

전달된 provider 문자열에 따라 적절한 모델 객체를 반환하는 핵심 함수입니다.

```python
def get_llm(provider="openai"):
    if provider == "openai":
        return ChatOpenAI(...) # OpenAI 객체 생성
    elif provider == "gemini":
        return ChatGoogleGenerativeAI(...) # Gemini 객체 생성
```

### 2. 모델 선택 및 초기화

실제로 어떤 모델을 사용할지 코드 한 줄로 결정할 수 있게 됩니다.

```python
# 필요에 따라 주석을 풀고 맺음으로써 모델을 교체합니다.
# llm = get_llm(provider="openai")
llm = get_llm(provider="gemini")
```

---

## 3. 코드 로직 분석 (통합 구조)

이 파일은 step07과 step08의 지식을 하나로 합친 완성형 구조를 보여줍니다.

1. 프롬프트 설계: ChatPromptTemplate을 통해 모델과 상관없는 공통적인 페르소나와 구조를 정의합니다.
2. 모델 생성 로직: get_llm 함수를 통해 다양한 공급자(Provider)를 수용할 준비를 합니다.
3. 대화 처리 루틴:
    * 최근 5개의 대화만 유지 (MAX_HISTORY).
    * Gradio 형식의 이력을 LangChain 형식으로 변환.
    * 템플릿에 데이터 주입 (format_messages).
    * 선택된 모델(llm)로 스트리밍 수행.

---

## 4. 학습 포인트

* 유연한 아키텍처: 특정 모델(OpenAI)에 종속되지 않고, 언제든지 다른 모델(Gemini)로 갈아탈 수 있는 코드 구조를 이해하는 것이 가장 중요합니다.
* 코드 재사용: 모델을 바꿀 때 chat 함수 내부 로직이 단 한 줄도 바뀌지 않는다는 점에 주목하세요. 이것이 LangChain을 활용한 개발의 정석입니다.
* 실무적 활용: 실제 서비스에서는 사용자의 설정이나 서버 상태에 따라 모델을 동적으로 바꿔야 할 때가 많습니다. 이 구조가 그 기반이 됩니다.

정리: step09은 "모델 독립적인 챗봇 설계"의 마침표입니다. 여기까지 이해하셨다면, 어떤 LLM이 새로 나와도
LangChain을 통해 즉시 자신의 서비스에 적용할 수 있는 능력을 갖추게 된 것입니다.
