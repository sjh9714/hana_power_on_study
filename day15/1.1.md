# RAG에서 **라우팅(Routing)** 이란?

> **사용자의 질문을 분석하여 가장 적절한 처리 경로(Path)를 선택하는 것**

입니다.

쉽게 말하면 네트워크의 Router가 목적지에 따라 패킷을 보내듯이,

```text
질문
 ↓
Router
 ↓
어디로 보낼까?
 ↓
적절한 처리 체인 선택
```

을 수행하는 역할입니다.

---

# 1. step01.py 코드에는 Router가 없다

현재 코드 구조는 다음과 같습니다.

```text
사용자 질문
      │
      ▼
Retriever
      │
      ▼
Prompt
      │
      ▼
GPT
      │
      ▼
답변
```

예를 들어

```text
농작물 재배관리 의사결정에 대해 알려줘
```

도

```text
GPT란?
```

도

```text
LangChain이란?
```

도

전부 동일하게

```text
Retriever → GPT
```

로 처리됩니다.

실제는 `농작물 재배관리 의사결정에 대해 알려줘`, `LangChain이란?` 검색어는 vectorDB에 저장되지 않았기 때문에 직접 GPT를 이용하여 처리하는 것이 더욱 좋은 흐름입니다.

# 2. Router를 추가하면

질문에 따라 경로가 달라집니다.

```text
  사용자 질문
       │
       ▼
     Router
       │
  ┌────┴──────┐
  ▼           ▼
  GPT        RAG
  │           │
  │           ▼
  │        Retriever
  │           │
  │           ▼
  │        Prompt
  │           │
  │           ▼
  │          GPT
  │           │ 
  └───────────┨
              ▼
             답변 
```

---

예시

### 질문 1

```text
작물모형을 이용한 웹 기반 밀 재배관리 의사결정 지원시스템
```

↓

```text
Router
 ↓
농업 문서 질문
 ↓
RAG
 ↓
Retriever
 ↓
GPT
```


↓

```text

```

# LangChain 관점에서 Router란?

LangChain에서는 Router를 보통

```python
RunnableLambda
```

또는

```python
RunnableBranch
```

로 구현합니다.

개념적으로는

```python
def router(query):

    if 농업질문:
        return rag_chain

    else:
        return general_chain
```

과 같습니다.

즉, 현재 시스템에서 **라우팅(Routing)** 은

> "사용자의 질문을 분석해서 GPT로 보낼지, RAG로 보낼지, 또는 어떤 Retriever로 보낼지를 결정하는 의사결정(Decision Making) 계층"

이라고 이해하시면 됩니다.

이 개념을 이해하면 다음 단계인 **LCEL의 RunnableBranch 기반 Router**, 그리고 **LangGraph의 Conditional Edge Router**를 훨씬 쉽게 이해할 수 있습니다.
