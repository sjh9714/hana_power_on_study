# 4.3 실제 코드 분석

예시

```python
from langchain_text_splitters import (
    RecursiveCharacterTextSplitter
)

def split_documents(
    documents
):

    splitter = (
        RecursiveCharacterTextSplitter(
            chunk_size=500,
            chunk_overlap=50
        )
    )

    chunks = (
        splitter.split_documents(
            documents
        )
    )

    return chunks
```

# 수업 중 강조

```text
RAG를 처음 배우는 사람들은

Embedding 모델이 가장 중요하다고 생각합니다.

하지만 실제 프로젝트를 해보면

Chunking이 성능을 결정하는 경우가 많습니다.

실제로

70점짜리 Embedding + 좋은 Chunk

가

90점짜리 Embedding + 나쁜 Chunk

보다 결과가 좋은 경우가 많습니다.

Chunk 전략은

RAG 개발자의 핵심 역량입니다.
```

# 예상 질문

### Q1

chunk_size는 무조건 큰 것이 좋은가요?

A.

아닙니다. 너무 크면 검색 정확도가 떨어집니다.

---

### Q2

chunk_overlap은 무조건 큰 것이 좋은가요?

A.

아닙니다. 너무 크면 중복 데이터가 많아집니다.

---

### Q3

RecursiveCharacterTextSplitter가 항상 최고인가요?

A.

대부분의 PDF에서는 좋은 선택이지만, Markdown, 코드, HTML은 전용 Splitter가 더 좋을 수 있습니다.

### 모범답안

```text

chunk_overlap은 인접 Chunk 간의 중복 영역을 유지하여
문맥 손실을 방지한다.

적절한 설정은 Retriever 검색 품질을 향상시킨다.
```
