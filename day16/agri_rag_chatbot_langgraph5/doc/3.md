# 3.8 Re-Rank 구현

예제

```python
query = (
    "APSIM 기반 생산량 예측"
)

docs = (
    retriever.invoke(
        query
    )
)
```

---

점수 계산

```python
pairs = [

    (
        query,
        doc.page_content
    )

    for doc in docs
]
```

---

실행

```python
scores =
reranker.predict(
    pairs
)
```

---

결과

```python
[
  0.98,

  0.34,

  0.81
]
```

---

# 정렬

```python
ranked_docs =
sorted(
    zip(
        docs,
        scores
    ),
    key=lambda x:x[1],
    reverse=True
)
```

# 예상 질문

### Q1

Re-Ranker만 사용하면 안 되나요?

100만 문서를 Cross Encoder로 비교하는 것은 비현실적입니다.

Retriever 없이 Re-Ranker 사용 가능한가요?

A.

가능하지만 실무적으로 거의 사용하지 않습니다.

---

### Q3

농업 논문 PDF에도 효과가 있나요?

A.

매우 효과적입니다.

특히 APSIM, DSSAT, FAO, NDVI 같은 전문 용어가 포함된 문서에서 효과가 큽니다.

## 주관식

### 3

Retriever와 Re-Ranker의 역할 차이를 설명하시오.

### 모범답안

```text
Retriever는 대량의 문서에서 관련 문서를 빠르게 검색하는 역할을 한다.

Re-Ranker는 Retriever가 찾은 후보 문서를 Question과 함께 다시 평가하여
가장 관련성이 높은 순서로 재정렬한다.

Retriever는 Recall 중심,
Re-Ranker는 Precision 중심의 기술이다.
```

# 다음 장 예고

제3권 제4장에서는

**Multi Query Retriever** 를 구현합니다.

여기서는 사용자의 질문을 LLM이 여러 형태로 재작성하여:

```text
"밀 생산량 예측"

↓

"밀 수확량 예측"

"밀 생산성 분석"

"밀 수확 예측 모델"

"밀 생산량 시뮬레이션"
```

과 같이 확장 검색하는 방법을 학습합니다.

이 단계부터는 단순 검색이 아니라 **질문 자체를 AI가 최적화하는 검색 구조**를 구현하게 됩니다.
