# `agri_rag_chatbot` 프로젝트에 Workflow + ReAct Agent 기능 추가

agri_rag_chatbot 프로젝트는 RAG Tool로 구성된 구조입니다.

기능 추가 단계

1. 원본 RAG 챗봇 이해
2. 채팅시 ReAct 에이전트 사용 기능 추가
3. State 추가
4. Workflow 추가
5. Agent 추가
6. Tool 추가
7. ToolNode 추가
8. Router 추가
9. 기존 RAG를 Tool로 변환
10. 최종 Hybrid LangGraph 완성

---

# 1단계 : 원본 RAG 챗봇 이해

먼저 원본 구조를 이해합니다.

```text
사용자
   │
   ▼
Router Chain
   │
   ├─ 일반대화
   │
   └─ RAG Chain
          │
          ▼
      Vector DB
```

특징

* LangChain 중심
* Router가 직접 분기
* Tool 개념 없음
* Graph 없음
* 상태(State) 없음

---

# 2단계 : State 추가

가장 먼저 해야 할 수정입니다.

새 파일

```text
agents/state.py
```

생성

예)

```python
from typing import TypedDict
from typing import Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import BaseMessage

class AgentState(TypedDict):
    # ReAct Agent 핵심 메모리
    messages: Annotated[
        list[BaseMessage],
        add_messages
    ]

    # 원본 질문
    user_question: str

    # 최종 응답
    final_answer: str

    # 향후 확장용
    user_id: str
    session_id: str
```

목적 : 공유 메모리(State) 기반으로 변경

```text
LangGraph의 핵심은 State
```

# 최종 구조

학습자가 최종적으로 이해해야 하는 그림

```text
                START
                  │
                  ▼
          Preprocess Node
                  │
                  ▼
             ReAct Agent
                  │
          Tool 필요한가?
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
     ToolNode          Postprocess
        │                   │
        ▼                   ▼
     ReAct Agent           END
```

그리고 실제 프로젝트에서는

```text
ToolNode
   │
   ├─ get_time
   │
   ├─ calculator
   │
   └─ rag_tool
           │
           ▼
      기존 RAG Chain
```

으로 연결됩니다.

교육용으로는 아래 순서가 가장 이해가 쉽습니다.

1. 원본 RAG 챗봇
2. State 추가
3. Workflow 추가
4. Agent 추가
5. Tool 추가
6. ToolNode 추가
7. Router 추가
8. 기존 RAG를 Tool로 변환
9. 최종 Hybrid LangGraph 완성

이 순서대로 진행하면 학습자는 "왜 LangGraph가 필요한지"와 "왜 Workflow + ReAct를 하이브리드 구조라고 부르는지"를 자연스럽게 이해할 수 있습니다.
