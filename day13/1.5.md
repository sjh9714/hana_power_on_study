# 벡터 데이터베이스(Vector Database)란?

텍스트, 이미지, 오디오 같은 **비정형 데이터**를 숫자의 배열 형태인 '벡터(Vector)'로 변환하여 저장하고, 이를 빠르게 검색할 수 있도록 최적화된 데이터베이스입니다.

---

## 1. 벡터 데이터베이스의 개념: '임베딩'의 이해

벡터 DB를 이해하려면 먼저 임베딩(Embedding)이라는 개념을 알아야 합니다.

컴퓨터는 "사과"라는 단어나 "강아지 사진"을 인간처럼 직관적으로 이해하지 못합니다. 따라서 인공지능 모델(Embedding Model)을 이용해 이 비정형 데이터의 '의미'를 추출하고, 이를 수백~수천 개의 숫자로 이루어진 좌표(벡터)로 변환합니다.

* **예시:** "왕"과 "여왕"은 의미가 비슷하므로 3차원 공간상의 거리가 매우 가깝게 배치됩니다. 반면 "자동차"는 멀리 배치됩니다.
* 벡터 DB는 이렇게 고차원 공간에 점으로 찍힌 **데이터들 간의 '거리(유사도)'를 계산하여 가장 비슷한 데이터를 찾아내는 역할**을 합니다.

---

## 2. 핵심 특징과 장점

### 1) 유사도 검색 (Similarity Search)

기존 DB가 단어나 숫자의 '완전 일치'를 기반으로 검색한다면, 벡터 DB는 '의미적 유사성'을 기반으로 검색합니다.

* "키우기 쉬운 반려동물"을 검색하면, "반려동물"이라는 단어가 없어도 "초보자용 고양이 사육법"이라는 문서를 찾아낼 수 있습니다.

### 2) 근사 최근접 이웃 (ANN, Approximate Nearest Neighbor) 알고리즘

고차원 벡터 공간에서 수억 개의 데이터 중 가장 가까운 점을 정확히 찾으려면 엄청난 시간이 걸립니다. 벡터 DB는 정확도를 아주 미세하게 양보하는 대신 속도를 획기적으로 높이는 ANN 알고리즘(예: HNSW, IVF 등)을 사용하여 밀리초(ms) 단위로 초고속 검색을 수행합니다.

### 3) LLM의 외부 기억 장치 역할 (RAG 구현)

최근 벡터 DB가 각광받는 가장 큰 이유입니다. LLM(예: ChatGPT, Qwen 등)은 학습하지 않은 최신 정보나 기업 내부 보안 데이터에 대해 거짓말(환각 현상)을 합니다. 이때 벡터 DB에 내부 문서를 저장해 두고, 사용자의 질문과 가장 유사한 문서를 찾아 LLM에게 제공하는 **RAG(검색 증강 생성)** 패턴의 핵심 컴포넌트로 활용됩니다.

---

## 3. 기존 RDBMS와의 차이점

기존의 관계형 데이터베이스(RDBMS, 예: MySQL, PostgreSQL, Oracle)와 벡터 데이터베이스는 데이터를 바라보는 패러다임 자체가 다릅니다.

| 비교 항목 | RDBMS (관계형 DB) | Vector DB (벡터 DB) |
| --- | --- | --- |
| **주요 데이터 형태** | 구조화된 데이터 (텍스트, 숫자, 날짜 등 정형 데이터) | 고차원 벡터 배열 (비정형 데이터에서 추출된 임베딩 값) |
| **데이터 매칭 방식** | **정확한 매칭 (Exact Match)** `WHERE id = 5` 또는 `LIKE '%사과%'` | **유사도 매칭 (Similarity Match)** 코사인 유사도, 유클리드 거리 등 활용 |
| **인덱싱 방식** | B-Tree, Hash Index 등 (빠른 값 비교 목적) | HNSW, IVF 등 (고차원 공간 내 근사 이웃 탐색 목적) |
| **검색 결과** | 조건에 일치하는 행(Row)들의 집합 | 질문과 가장 유사한 순서대로 정렬된 탑 K(Top-K) 결과 |
| **주요 활용 분야** | 금융 트랜잭션, 회원 관리, ERP 등 정밀 데이터 관리 | AI 추천 시스템, LLM (RAG), 이미지/동영상 검색, 챗봇 |

### 💡 요약

* **RDBMS**는 "내가 지정한 **정확한 단어/값**이 포함된 데이터를 찾아줘" 시스템이고,
* **Vector DB**는 "내가 준 데이터와 **맥락이나 의미가 가장 비슷한 것**들을 골라줘" 시스템입니다.

---

## 4. 대표적인 벡터 DB 종류

현재 시장에서 자주 쓰이는 벡터 DB는 크게 두 가지 부류로 나뉩니다.

* **전용 벡터 DB (Pure Vector DB):** 처음부터 벡터 검색만을 위해 설계되어 대용량 벡터 처리에 극도로 최적화된 DB입니다.
  * *Milvus, Qdrant, Pinecone, Weaviate, ChromaDB* 등

* **기존 DB의 확장 확장 플러그인:** 익숙한 기존 DB에 벡터 검색 기능을 추가한 형태입니다.
  * *pgvector* (PostgreSQL 확장), *Elasticsearch* (KNN 플러그인) 등

---

## 5. 크로마DB(ChromaDB)란?

크로마DB(ChromaDB)는 인공지능(AI) 개발자들, 특히 LLM(거대언어모델) 기반 애플리케이션이나 챗봇을 만드는 빌더들 사이에서 **가장 가볍고 빠르게 시작할 수 있어 큰 인기를 끌고 있는 오프소스 벡터 데이터베이스**입니다.

앞서 설명해 드린 전용 벡터 DB 중 하나로, 파이썬(Python) 중심의 개발 환경에 아주 최적화되어 있습니다. 어떤 특징과 장점을 가졌는지 알아보겠습니다.

---

### 1. 크로마DB의 핵심 특징

### 1) "In-Memory" 기반의 미친듯한 간결함

크로마DB의 가장 큰 무기는 **설치와 사용이 극도로 간단하다**는 점입니다.
별도의 무거운 데이터베이스 서버를 띄우지 않고도, 파이썬 코드 내에서 `import chromadb` 한 줄로 메모리 상에 데이터베이스를 즉시 구동할 수 있습니다. (SQLite처럼 파일 형태로 로컬에 저장하는 것도 매우 쉽습니다.)

* 마치 파이썬 가상환경 안에서 도구 상자를 꺼내 쓰듯 가볍게 로컬 개발 및 프로토타이핑을 할 수 있습니다.

### 2) Embedding 모델 내장 (Batteries Included)

일반적인 벡터 DB는 텍스트를 벡터로 바꾸는 '임베딩 과정'을 개발자가 직접 구현해야 합니다. 반면 크로마DB는 기본적으로 **Sentence Transformers 같은 임베딩 모델을 내장**하고 있습니다.

* 개발자가 그냥 생(Raw) 텍스트를 집어넣으면, 크로마DB가 알아서 숫자로 바꾸고(임베딩) 저장까지 자동으로 처리해 줍니다. oczywiście OpenAI, Hugging Face, Cohere 등의 외부 API와도 쉽게 연동됩니다.

### 3) AI 생태계(LangChain, LlamaIndex)와의 완벽한 궁합

LLM 애플리케이션 개발에 표준처럼 쓰이는 프레임워크인 LangChain(랭체인)이나 **LlamaIndex**와 거의 완벽하게 통합됩니다. 코드 몇 줄만으로 문서를 쪼개고, 크로마DB에 넣고, LLM과 연결하는 RAG(검색 증강 생성) 파이프라인을 구축할 수 있습니다.

---

### 2. 기존 벡터 DB들과의 비교 (장점과 한계)

| 특징 | 크로마DB (ChromaDB) | 대형 전용 벡터 DB (예: Milvus, Pinecone) |
| --- | --- | --- |
| **적합한 규모** | 소규모, 개인 프로젝트, 로컬 프로토타이핑 | 엔터프라이즈급, 수억 건 이상의 대용량 데이터 |
| **인프라 부담** | 없음 (로컬 파일이나 메모리에서 동작) | 큼 (서버 클러스터를 띄우거나 클라우드 비용 발생) |
| **학습 곡선** | 매우 낮음 (파이썬 개발자에게 매우 친숙) | 보통 (인프라 및 DB 아키텍처 이해 필요) |

#### 👍 장점

* **빠른 PoC(개념 검증):** 아이디어를 빠르게 코드로 구현하고 테스트해 보기에 이보다 좋은 선택지가 없습니다.
* **오픈소스 및 무료:** 라이선스 비용 걱정 없이 로컬이나 자체 서버에 올려 쓸 수 있습니다.
* **메타데이터 필터링:** 벡터 유사도 검색뿐만 아니라, "2026년에 작성된 문서만 찾아줘" 같은 일반적인 조건 필터링도 동시에 지원합니다.

#### 👎 한계

* **스케일아웃(확장성)의 제한:** 수천만~수억 건의 고차원 벡터를 분산 처리해야 하는 대규모 운영 환경에서는 Milvus나 Qdrant 같은 분산 아키텍처 기반의 DB에 비해 성능이나 안정성이 떨어질 수 있습니다. (최근에는 분산형 아키텍처도 계속 업데이트 중입니다.)

---

### 3. 언제 크로마DB를 쓰면 좋을까요?

* 노트북이나 단일 PC 환경에서 **나만의 로컬 LLM 챗봇**을 만들고 싶을 때
* 기업 내부 데이터를 활용한 RAG 시스템의 프로토타입(시제품)을 빠르게 검증하고 싶을 때
* 데이터 용량이 기가바이트(GB) 단위 이하로, 복잡한 인프라 관리 없이 **가볍고 독립적인 AI 서비스**를 구축하고 싶을 때

요약하자면, 크로마DB는 "AI 애플리케이션 개발의 진입 장벽을 낮춰주는 가장 친절하고 가벼운 벡터 저장소"라고 보시면 됩니다.

파이썬(Python) 환경에서 크로마DB(ChromaDB)를 사용하여 데이터를 저장하고, 의미 기반의 유사도 검색을 수행하는 간단하고 명확한 예제를 소개해 드리겠습니다.

이 예제는 외부에 데이터를 보내지 않고, 개발자 PC의 로컬 디렉토리에 데이터를 영구 저장(Persistence)하며, 크로마DB에 **내장된 기본 임베딩 모델**을 사용하여 텍스트를 자동으로 벡터화하는 구조입니다.
