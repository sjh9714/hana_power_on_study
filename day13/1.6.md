# 1. 크로마DB(ChromaDB) 사용법

## 1. 사전 준비 (라이브러리 설치)

터미널이나 커맨드 창에 아래 명령어를 입력하여 크로마DB 라이브러리를 설치합니다.

```bash
pip install chromadb

```

`pip install langchain-chroma`나 `pip install chromadb`를 설치할 때 `C/C++ 컴파일러가 필요하다`거나 **`Microsoft Visual C++ 14.0 or greater is required`** 같은 에러 메시지를 마주치는 경우가 많습니다.

파이썬 라이브러리를 설치하는데 왜 자바나 파이썬이 아닌 **C/C++ 컴파일러**가 필요할까요? 그 이유는 크로마DB의 핵심 심장부 알고리즘이 **고속 처리를 위해 순수 C++로 작성되었기 때문**입니다.

---

### 1. 핵심 원인: C++ 기반의 고속 벡터 인덱싱 엔진 (`hnswlib`)

앞서 크로마DB의 내부 구조를 설명해 드릴 때, 벡터 데이터의 거리를 계산하고 고속으로 유사도를 검색하는 핵심 엔진으로 **HNSW(Hierarchical Navigable Small World)** 알고리즘을 사용한다고 말씀드렸습니다.

크로마DB는 이 HNSW 알고리즘을 구현하기 위해 내부적으로 `hnswlib`라는 오픈소스 라이브러리에 의존합니다.

* **왜 C++인가?:** 수만 차원, 혹은 수억 건의 데이터 공간에서 고차원 수학 연산(코사인 유사도, 유클리드 거리 등)을 밀리초(ms) 단위로 끝내려면 CPU와 메모리를 극도로 제어할 수 있는 **최고 수준의 연산 속도**가 필요합니다. 파이썬은 인터프리터 언어 특성상 이런 대규모 루프 연산과 메모리 제어 인터럽트 처리에 속도 한계가 있으므로, 핵심 코어 엔진을 C++로 작성한 것입니다.
* **컴파일러가 필요한 이유:** 파이썬 패키지 관리자인 `pip`가 크로마DB를 설치하는 과정에서 이 C++로 작성된 소스 코드(`hnswlib`)를 가져옵니다. 이때 사용자의 운영체제(Windows, Mac, Linux) 환경에 맞게 기계어로 번역하는 **'컴파일(Compile)'** 과정을 거쳐야만 파이썬이 이를 불러와 쓸 수 있는 바이너리(pyd 또는 so 파일)가 생성됩니다. 내 컴퓨터에 C/C++ 컴파일러가 없으면 이 번역 작업을 할 수 없어 에러가 나는 것입니다.

---

### 2. 왜 어떤 컴퓨터는 그냥 설치되고, 어떤 컴퓨터는 에러가 날까? (Wheel의 개념)

파이썬 생태계에는 Wheel(`.whl`)이라는 미리 컴파일된 바이너리 패키지 형태가 존재합니다.

* **Wheel 패키지가 있는 경우:** 라이브러리 개발자가 윈도우용, 맥용 등으로 C++ 코드를 미리 다 컴파일해서 패키지 저장소(PyPI)에 올려두었다면, 사용자는 컴파일러 없이 그냥 다운로드만 받아서 쓸 수 있습니다.
* **직접 빌드(Source Distribution)해야 하는 경우:** * 파이썬의 특정 버전(예: 최신 파이썬 버전)이나 특정 OS 환경에 맞는 미리 컴파일된 파일(`wheel`)이 저장소에 없을 때
* `langchain-chroma`나 `chromadb`가 업데이트되면서 내부 C++ 확장 모듈의 소스코드를 사용자의 시스템 환경에서 직접 빌드해야 할 때

이 경우 `pip`는 자동으로 소스 코드(`.tar.gz`)를 내려받은 뒤 사용자의 PC에서 직접 컴파일을 시도하게 되며, 이때 컴파일러가 없으면 에러가 발생합니다.

### 3. 해결 방법 (OS별 컴파일러 설치 가이드)

에러를 해결하려면 내 시스템에 C++ 컴파일러 도구를 설치해 주면 됩니다.

### 1) Windows (가장 자주 에러가 발생하는 환경)

윈도우 환경에는 기본 C++ 컴파일러가 내장되어 있지 않기 때문에 마이크로소프트의 빌드 도구를 설치해야 합니다.

* [Visual Studio Build Tools 다운로드 페이지]에 접속합니다.
* `Desktop 개발용 C++ 컴파일러` 또는 **`C++를 사용한 데스크톱 개발`** 워크로드를 체크하고 설치를 진행합니다. (MSVC 컴파일러와 Windows SDK가 설치됩니다.)

### 2) macOS

맥 환경에서는 터미널을 열고 애플의 개발자 명령줄 도구를 설치하면 간단히 해결됩니다.

```bash
xcode-select --install

```

### 3) Linux (Ubuntu/Debian)

리눅스는 패키지 관리자를 통해 완결성 있는 빌드 도구 모음(`build-essential`)을 설치해 주면 됩니다.

```bash
sudo apt-get update
sudo apt-get install build-essential Python3-dev

```

## 2. 크로마DB 기초 실습 코드

"도서 추천 시스템"을 간단히 모델링 코드입니다. 책의 요약본(텍스트)을 저장한 후, 사용자의 질문과 맥락상 가장 유사한 책을 찾아냅니다.

>파일명 : step9.py

```python
import chromadb

# 1. 크로마DB 클라이언트 생성 (데이터를 파일로 저장할 경로 지정)
# 데이터를 휘발시키지 않고 './my_chroma_db' 폴더에 영구 보관합니다.
client = chromadb.PersistentClient(path="./my_chroma_db")

# 2. 컬렉션(Collection) 생성 또는 가져오기
# RDBMS의 테이블(Table)에 해당하는 개념입니다.
collection = client.get_or_create_collection(name="book_recommendation")

# 3. 데이터 준비 (도서 요약 정보)
# 문서 데이터, 각 문서의 고유 ID, 검색 필터링을 위한 메타데이터를 준비합니다.
documents = [
    "파이썬을 활용한 머신러닝과 딥러닝 실무 가이드. 데이터 전처리부터 모델 배포까지 다룹니다.",
    "자바 스프링 부트 기반의 엔터프라이즈 웹 애플리케이션 아키텍처 및 백엔드 개발.",
    "쿠버네티스와 도커를 이용한 마이크로서비스 아키텍처 구축 및 Devops 인프라 실무.",
    "시간 흐름에 따른 데이터 분석과 LSTM, RNN 기반의 시계열 딥러닝 예측 모델링.",
    "맛있는 이탈리아 파스타 요리 레시피와 토마토 소스 숙성 비법 가이드."
]

ids = ["book_01", "book_02", "book_03", "book_04", "book_05"]

metadatas = [
    {"category": "AI/Data", "year": 2025},
    {"category": "Backend", "year": 2024},
    {"category": "DevOps", "year": 2026},
    {"category": "AI/Data", "year": 2026},
    {"category": "Cooking", "year": 2023}
]

# 4. 컬렉션에 데이터 추가
# 따로 임베딩 모델을 지정하지 않으면 내장된 SentenceTransformer 모델이 
# 자동으로 텍스트를 고차원 벡터로 변환(임베딩)하여 저장합니다.
print(">> 데이터를 벡터 데이터베이스에 인덱싱하는 중...")
collection.add(
    documents=documents,
    ids=ids,
    metadatas=metadatas
)
print(">> 인덱싱 완료!\n")


# 5. 유사도 검색 수행 (Semantic Search)
# 사용자는 구체적인 단어 대신 '의미적 맥락'으로 질문을 던집니다.
query_text = "컨테이너 기반의 클라우드 배포 인프라를 공부하고 싶어"

print(f"🔍 유저 질문: '{query_text}'")
print("-" * 50)

# 쿼리 전송 (가장 유사한 상위 2개의 결과를 요청)
results = collection.query(
    query_texts=[query_text],
    n_results=2
)

# 6. 결과 출력
for i in range(len(results['documents'][0])):
    doc = results['documents'][0][i]
    doc_id = results['ids'][0][i]
    meta = results['metadatas'][0][i]
    distance = results['distances'][0][i]  # 거리가 가까울수록(작을수록) 유사도가 높음
    
    print(f"[순위 {i+1}] ID: {doc_id} (거리 점수: {distance:.4f})")
    print(f"카테고리: {meta['category']} / 발행년도: {meta['year']}")
    print(f"내용 요약: {doc}")
    print("-" * 50)

```

## 3. 코드의 단계별 상세 설명

### 1) `PersistentClient(path=...)`

* `chromadb.Client()`를 사용하면 휘발성 메모리(In-Memory)에만 상주하여 프로그램이 끝나면 데이터가 사라집니다.
* 반면 `PersistentClient`를 쓰면 지정한 경로(`./my_chroma_db`)에 SQLite 파일과 HNSW 인덱스 파일이 생성되어 **데이터가 영구 보관**됩니다. 다음 번에 코드를 다시 실행할 때 데이터를 새로 넣지 않고 불러와 쓸 수 있습니다.

### 2) `get_or_create_collection(name=...)`

* 크로마DB의 컬렉션(Collection)은 데이터를 묶는 단위입니다.
* 기존 RDBMS의 '테이블' 개념과 유사하지만, 스키마(데이터 구조)를 엄격하게 정의할 필요 없이 문서, 벡터, 메타데이터를 유연하게 수용합니다.

### 3) `collection.add(...)`

* 이 메서드가 실행될 때 크로마DB 내부에서는 매우 중요한 작업이 일어납니다.
* 입력된 `documents`의 문자열을 내장 임베딩 모델(기본값: `all-MiniLM-L6-v2`)로 전달하여 384차원의 숫자 배열(벡터)로 변환한 후, 이 벡터 값을 C++ 기반의 고속 HNSW 인덱스 공간에 좌표로 찍어 저장합니다.

### 4) `collection.query(...)`

* 사용자가 검색어(`query_text`)를 던지면, 크로마DB는 이 질문 역시 **동일한 384차원 벡터 공간의 좌표로 변환**합니다.
* 그 후 공간 내에서 유저 질문 좌표와 **가장 가까운 거리(Distance)에 있는 데이터 점들**을 찾아서 순서대로 반환합니다.

> **💡 결과 확인 팁:** > 검색 결과 데이터 중에서 `results['distances']` 값이 반환되는데, 이는 벡터 간의 거리를 뜻합니다. 크로마DB의 기본 거리 측정 방식에서는 **이 숫자가 0에 가까울수록(작을수록) 맥락상 매우 일치하는 데이터**임을 뜻합니다.

## 4. 메타데이터 필터링 응용 (Advanced)

크로마DB는 벡터 검색을 하면서 RDBMS처럼 조건을 걸어 필터링을 동시 수행할 수 있습니다. 예를 들어, "AI/Data 카테고리이면서 2026년에 나온 시계열 관련 서적"만 추려내고 싶다면 쿼리 부분을 아래와 같이 바꿀 수 있습니다.

```python
results = collection.query(
    query_texts=["시계열 예측 모델 알고리즘"],
    n_results=1,
    where={"$and": [
        {"category": "AI/Data"},
        {"year": 2026}
    ]}
)

```

이처럼 크로마DB는 가볍지만 비정형 데이터의 '의미 기반 검색'과 정형 데이터의 '조건 필터링'을 동시에 완벽하게 처리하는 강력한 기능을 제공합니다.

결론부터 말씀드리면, 크로마DB가 **텍스트(영어 문장 등)를 벡터(숫자 배열)로 변환하는 작업을 '내 컴퓨터(로컬) 내부'에서 직접 수행하기 위해 필요한 인공지능 임베딩 모델의 파일들을 다운로드하는 중**입니다.

---

### 1. 다운로드되는 파일의 정체: `all-MiniLM-L6-v2`

앞서 크로마DB는 별도의 설정을 하지 않으면 "기본 임베딩 모델을 내장하고 있다"고 말씀드렸습니다. 바로 그 기본 모델의 이름이 `all-MiniLM-L6-v2`입니다.

* **임베딩 모델의 역할:** 사용자가 입력한 "쿠버네티스와 도커를 이용한..." 같은 텍스트를 고차원 공간의 좌표(384개의 숫자로 이루어진 벡터)로 바꾸는 뇌 역할을 합니다.
* **OpenAI 등과의 차이점:** OpenAI의 API(text-embedding-3-small 등)를 쓰면 인터넷을 통해 돈을 내고 벡터 값을 받아와야 하지만, 크로마DB는 이 가벼운 오픈소스 모델을 유저의 로컬 PC로 다운로드받아 **인터넷 연결이나 비용 없이 오프라인으로 벡터 변환을 처리**할 수 있게 해줍니다.

---

### 2. 경로와 확장자명에 담긴 의미

경로를 가만히 뜯어보면 크로마DB가 어떻게 작동하는지 개발자 관점에서 아주 흥미로운 대목들을 볼 수 있습니다.

### 1) `.cache\chroma\onnx_models\`

* 모델을 매번 실행할 때마다 다운로드하면 비효율적이므로, 윈도우 사용자 계정(`C:\Users\masun`)의 **캐시(Cache) 디렉토리**에 모델을 딱 한 번만 다운로드해 두고 재사용하겠다는 의미입니다. 다음 실행부터는 다운로드 과정 없이 즉시 실행됩니다.

### 2) `onnx.tar.gz`

* 여기서 ONNX(Open Neural Network Exchange)라는 확장자가 핵심입니다.
* 보통 딥러닝 모델은 파이토치(PyTorch)나 텐서플로우(TensorFlow) 같은 무거운 프레임워크가 설치되어 있어야만 실행할 수 있습니다.
* 하지만 크로마DB는 가벼움을 지향하기 때문에, AI 모델을 어떤 환경에서든 프레임워크 없이 칩셋 레벨에서 빠르게 구동할 수 있도록 경량화 최적화 포맷인 **ONNX 포맷**으로 패키징된 모델을 가져와 내부적으로 `onnxruntime`을 통해 구동하는 것입니다.
