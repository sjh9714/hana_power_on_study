# RAG란?

**RAG(Retrieval-Augmented Generation)** 는 한국어로 **검색 증강 생성**이라고 하며,

LLM(대규모 언어 모델)이 답변을 생성하기 전에 **외부 문서나 데이터베이스에서 관련 정보를 검색(Retrieval)** 한 후, 그 정보를 바탕으로 **답변을 생성(Generation)** 하는 기술입니다.

---

## 왜 RAG가 필요한가?

일반적인 LLM은 학습된 데이터만 이용합니다.

예를 들어:

> "우리 회사의 2026년 내부 규정을 알려줘"

라고 질문하면,

* ChatGPT는 회사 내부 문서를 학습하지 않았음
* 최신 문서도 알 수 없음
* 따라서 정확한 답변 불가능

하지만 RAG는:

1. 회사 문서를 검색 하여
2. 관련 내용 추출 할 수 있습니다
3. 추출된 내용을 LLM에 전달하면
4. LLM이 답변 생성 합니다

과정을 수행합니다.

---

## RAG 동작 구조

```text
사용자 질문
      │
      ▼
문서 검색(Retrieval)
      │
      ▼
관련 문서 추출
      │
      ▼
Prompt 생성
      │
      ▼
LLM
      │
      ▼
최종 답변
```

예시:

```text
질문:
"대출 금리 우대 조건은?"

↓ 검색

은행 상품 설명서 PDF

↓ 추출

"급여 이체 고객 0.5% 우대"

↓ LLM

"급여 이체 고객은 최대 0.5% 금리 우대를 받을 수 있습니다."
```

# RAG 구성 요소

## 1. 문서(Document)

예:

* PDF
* Word
* Excel
* 웹페이지
* 사내 Wiki
* DB 데이터

---

## 2. Chunking

문서를 작은 단위로 나눔

예:

```text
100페이지 PDF
 ↓

500자 단위로 분할

Chunk1
Chunk2
Chunk3
...

```

---

## 3. Embedding

텍스트를 벡터로 변환

예:

```text
"대출 금리"

↓

[0.123, 0.451, 0.887, ...]
```

사용 모델:

* OpenAI Embedding
* Gemini Embedding
* BGE
* E5
* SentenceTransformer

---

* Chroma
* FAISS

# Fine-Tuning과 RAG 차이

| 구분        | Fine-Tuning | RAG             |
| ----------- | ----------- | --------------- |
| 목적        | 모델 학습   | 문서 검색       |
| 비용        | 높음        | 낮음            |
| 최신 데이터 | 어려움      | 쉬움            |
| 문서 변경   | 재학습 필요 | 재색인만 수행   |
| 구현 난이도 | 높음        | 상대적으로 쉬움 |

예:

### Fine-Tuning

```text
모델 자체를 학습
```

### RAG

```text
문서를 검색 후 답변
```

# LangChain 기반 RAG 흐름

```text
PDF
 ↓
Loader
 ↓
Text Splitter(Chunking)
 ↓
Embedding
 ↓
Vector DB
 ↓
Retriever
 ↓
Prompt
 ↓
LLM
 ↓
Answer
```

위와 같은 흐름으로 진행을 하지만 실제는 2개의 부분을 분리 하여 진행합니다.

```text
             [사전 작업(Indexing Time)]

PDF
 ↓
Loader
 ↓
Chunking
 ↓
Embedding
 ↓
Qdrant 저장



              [검색 시점(Retrieval Time)]

User Question
       ↓
Router
       ↓
Retriever Node
       ↓
Qdrant Search
       ↓
Prompt Node
       ↓
LLM Node
       ↓
Answer
```

주로 사용하는 패키지:

```python
PyPDFLoader
RecursiveCharacterTextSplitter
OpenAIEmbeddings
Chroma
Retriever
ChatOpenAI
```

# 금융 분야에서의 RAG 활용

금융 AI 챗봇 예시:

```text
투자설명서 PDF
약관 PDF
상품 설명서 PDF
내부 업무 문서
```

↓

```text
Chroma DB 저장
```

↓

```text
질문:
"하나은행 적금 우대금리는?"
```

↓

```text
RAG 검색
```

↓

```text
정확한 답변 생성
```

이 방식은 금융, 법률, 의료, 기업 내부 문서 검색 시스템에서 가장 많이 사용되는 LLM 아키텍처 중 하나입니다.

**PDF → ChromaDB → LangChain → OpenAI/Gemini 챗봇** 프로젝트가 바로 전형적인 RAG 시스템입니다.
